Core engine

Autograd architecture

TensorF implements a dynamic, define-by-run computation graph — the same mental model as PyTorch/autograd — across three layers: pure algebra (Matrix<T>), graph nodes (Tensor<T>), and differentiable operations (Operation<T> subclasses).

Three layers

1 · Matrix<T>

Flat std::vector<T> data with a shape_t shape and precomputed strides (numElementsSeen). Row-major. A Broadcast<T> friend class handles NumPy-style shape diffusion. No notion of gradient — this is algebra only.

2 · Operation<T>

Abstract base for 19 concrete operations. Each knows its inputs (t1, sometimes t2), computes a forward output, and back-propagates a gradient into its inputs via backward(Matrix<T> grad).

3 · Tensor<T>

Wraps a value Matrix<T> val, a gradient Matrix<T> grad, and a backOp pointer to the Operation that produced it. The node the user actually manipulates, always through Tensor_t<T> = std::shared_ptr<Tensor<T>>.

The graph is built implicitly. Writing a->matmul(b) (or a + b via the operator overloads) constructs an Operation with std::make_shared, executes its forward(), and returns a Tensor_t<T> whose backOp points at that operation. This chaining materializes the DAG for the backward pass.

Backpropagation — Tensor::backward

  1. Accumulates the incoming gradient (adds to any existing gradient — necessary when a tensor is reused multiple times in the graph, e.g. residual connections).
  2. Checks for NaN via Matrix<T>::hasNaN; throws if found.
  3. Delegates to backOp->backward(ingrad), which computes local gradients and recursively calls backward() on its own inputs.

Memory management & the shared_ptr cycle

Tensor and Operation reference each other via shared_ptr (Tensor::backOp → Operation, and each Operation holds its input Tensor_ts). This is a reference-counting cycle that never frees itself without manual intervention.

MethodRoleEffect on the graph
zero_grad()Resets gradients to zeroGraph remains usable
reset_graph()Breaks the Tensor→Operation→Tensor cyclesbackOp = nullptr, propagated recursively; memory is freed

Every operation implements reset_graph() the same way: call reset_graph() on its inputs, then null its own reference. This is why every training loop in the codebase ends its iteration with loss->reset_graph() — skip it and the graph leaks.

Broadcasting — Broadcast<T>

A utility class, declared friend of Matrix<T>, implementing NumPy-style broadcasting:

  • assertBroadcast — compares shapes from the trailing dimension inward, tolerating a size-1 dimension on either side; recurses symmetrically when the two tensors have different ranks (right-aligned, as in NumPy).
  • computeBroadcastResultShape — the max of compatible dimensions.
  • broadcastTo(source, new_shape) — rebuilds an array at the target size, "freezing" size-1 dimensions at index 0 during replication. Includes a defensive bounds check (source.data.size() < expectedSourceSize → throws) added after a prior silent-segfault bug.

Matrix<T>'s +, -, *, / operators call this mechanism automatically whenever operand shapes differ.

Matrix products — dot() and matmul()

dot(rhs) dispatches on dimensionality:

  • 1D·1D → classic scalar product (dotProduct1D, simple loop).
  • 2D·2D → dotProduct2D, which calls cblas_sdot/cblas_ddot for float/double, or a naive loop otherwise (needed for custom types like fp8/fp4).
  • Other shapes → checks dotShapesAssert (rhs's second-to-last dim must match this's last dim), then delegates to a generic path built on matProduct2D.

matmul(rhs) explicitly rejects the 1D·1D case ("use dot() instead"). It computes the output shape (shape[:-1] + rhs.shape[-1]), allocates an AVX2-padded output buffer (avx2_pad(n) = ((n+7)/8)*8), then recurses over batch dimensions until reaching the last two, where it calls matProduct2D — backed by cblas_sgemm/cblas_dgemm for float/double. The recursion natively handles a 2D weight matrix shared across a 3D batch (a Linear layer's weight against a {B,T,D} input).

Batched matmul backward MatmulOperation::backward specifically transposes only the last two dimensions when the input is 3D (permutation {0,2,1}) — consistent with this batched forward implementation.

Reductions

  • sum() with no axis returns a scalar T (sum_1D), not a Matrix<T> — SumOperation::forward() wraps it back into Matrix<T>(s).
  • sum(axis) handles 1D/2D directly (sum_2D) and generalizes to ND tensors recursively via an index stack — logic parallel to, but independently reimplemented from, SumAxisOperation::backward's inverse broadcast (see Known Issues #6).
  • mean(axis), var(axis, ddof0), std(axis) are correct ND implementations, with optional Bessel's correction (ddof0=false → divide by n-1).

The chain rule under broadcasting — sumGradForBroadcast

Defined in Matrix.hpp and used by nearly every binary operation to reduce a gradient back to an operand's original shape after forward-pass broadcasting:

  1. Sums excess leading dimensions while the gradient's rank exceeds the original shape's rank.
  2. For each remaining dimension where the original shape was 1 but the gradient has size >1, sums that dimension (reinserting a size-1 dimension if needed).
  3. Applies a final shape correction if necessary.

This is what concretely implements the chain rule in the presence of broadcasting — the equivalent of what PyTorch does internally for broadcasted operations.

OpenBLAS dependency

Matrix.hpp includes <cblas.h> directly and calls cblas_sdot/cblas_ddot/cblas_sgemm/cblas_dgemm for float/double. This is why OpenBLAS must be linked at compile time (see Install → Dependencies), and why custom numeric types (fp8, fp4) always take the non-BLAS fallback path (naive loops).

The 19 operations

Every differentiable primitive in TensorF is one of these. Full forward/backward math for each is on the Operations reference page; summary:
