API reference · DataLoader/*.hpp

DataLoader

Everything that turns files on disk into Matrix<T>/Tensor_t<T> batches: text corpora, tabular CSV/TSV, images, NumPy arrays, GGUF checkpoints, plus TensorF's own binary serialization and block-wise quantization formats.

Dataset<T>

Wraps a feature matrix X {n_samples, n_features} and label matrix Y {n_samples, n_outputs}, validating matching row counts at construction. size() and get(idx) give indexed sample access — the generic base for tabular/classical ML workflows.

TextDataset<T>

TextDataset(std::string folder, size_t block_size, size_t batch_size, uint32_t seed=42)

Character-level language modeling dataset. load() reads text files from folder, splits 90/10 into train/val by character count, builds a character-level vocabulary (stoi/itos), and encodes both splits to integer token ids.

usage
TextDataset<float> ds("Dataset", /*block_size=*/16, /*batch_size=*/8);
ds.load();
auto [x, y] = ds.get_batch("train");   // random contiguous window sampling

LazyDataLoader<T>

A thin wrapper around TextDataset<T> that loads eagerly at construction and exposes a single getNextBatch(split="train") call — the shape federated clients use when pulling local training batches (see Federated Learning).

Tabular<T>

CSV/TSV reader via plain std::ifstream (native support, no dependency). An enum TYPE{CSV,TSV,XLS,XLSX} exists, but XLS/XLSX require linking against libxls/OpenXLSX separately — not bundled.

NPYLoader

Loads NumPy .npy single-array files directly into Matrix<T>, implementing the official .npy format spec. Useful for bringing preprocessed datasets in from a Python/NumPy pipeline.

ImageLoader

Loads images via a bundled stb_image.h into Matrix<T> / Tensor_t<T>.

GGUF — low-level GGUF file reader

Parses the raw GGUF binary container: tensor metadata (TensorInfo: name, dimensions, ggml_type, byte offset), key-value metadata (scalar and array), and supports the common GGML quantization type tags (F32, F16, Q4_0, Q4_1, Q8_0, Q4_K, Q5_K, Q6_K). This is the file ModelLoader's GGUFLoader<T> builds on top of to actually populate a GPT<T> or Llama<T>.

Serializer<T>

TensorF's own binary checkpoint format — what Module::save()/load() use.

on-disk layout (little-endian)
┌────────────────────────────────────────────┐
│  Magic bytes: "TNSF"          (4 bytes)     │
│  Version:                     (uint32_t)    │
│  Number of tensors:           (uint64_t)    │
├────────────────────────────────────────────┤
│  For each tensor:                           │
│    Rank (number of dims):     (uint32_t)    │
│    Each dim size:             (int64_t × rank) │
│    Number of elements:        (uint64_t)    │
│    Raw data:                  (T × n_elements) │
└────────────────────────────────────────────┘

Quantizer — quant:: namespace

Block-wise quantization between a full-precision compute type (float/double — whatever T the model actually trains in) and a narrow software float storage type (FP8<E,M> / FP4<E,M>).

Every contiguous run of group elements (default 32, matching GGUF's own convention) shares one float absmax scale — the same symmetric-absmax scheme used by GPTQ, AWQ, GGUF, and the MX formats:

encode:  code  = QT(value / scale)
decode:  value = float(code) * scale
Why not just cast Matrix<float> → Matrix<FP4>? A plain std::vector<FP4<E,M>> is not 4-bit-per-element — each FP4 struct is still one byte in memory. Real savings come from two things this module actually does: (1) the per-block float scale, which is what gives a 4-bit float usable dynamic range at all, and (2) genuine bit-packing on save (two 4-bit codes per byte), applied only at save_quantized/load_quantized time — the in-memory QuantTensor stays one struct per element for easy arithmetic.
FunctionPurpose
save_quantized<QT,SrcT>(params, path, group=32)Quantize + bit-pack a parameter list to disk
load_quantized<QT,DstT>(path)Dequantize straight back to Matrix<DstT>
save_module<QT>(module, path, group=32)Convenience wrapper: save_quantized over module.parameters()
load_module_into<QT>(module, path)Dequantizes and copies straight into an existing module's parameters (tensor count must match)

Used by Trainer::save_quantized_checkpoint for ~4× (FP8) or ~8× (FP4) smaller checkpoints on disk — training still happens in full-precision T, only the bytes at rest shrink.
