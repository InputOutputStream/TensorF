Transformers — GPT, GPT-LoRA, Llama

Three decoder-only transformer stacks share the same Module<T> composition pattern but differ in normalization, feed-forward, and position-encoding strategy. All three implement forward(index, targets, apply_mask), generate(...), and train(...) with an identical shape.

GPT<T>

GPT-2 architecture. Learned absolute positional embeddings, LayerNorm, GeLU feed-forward, standard multi-head attention.

Llama<T>

Llama/SmolLM2 architecture. RoPE (rotary position embeddings) applied inside each head, RMSNorm, SwiGLU feed-forward.

GPTLoRA<T>

A GPT variant whose LM head is a LoRALinear, for federated distillation with a frozen backbone.

GPT<T>

GPT(size_t vocab_size, size_t input_dim, size_t block_size, size_t n_heads, size_t n_layer)

Composes: PositionalEncoding, Embedding, a stack of n_layer Block<T>s, a final LayerNorm (ln_f), and an LM head (Linear<T> projecting to vocab_size).

GPT::forward(index, targets, apply_mask=true)

tok_embed = embedding_table(index)                       // {B,T,D}
pos_embed = position_embedding_table(arange(T))           // {1,T,D}, broadcasts vs. batch
x = tok_embed + pos_embed

for block in decoder_blocks: x = block(x, apply_mask)

x = ln_f(x)
logits = lm_head(x)                                       // {B,T,vocab_size}

if targets != nullptr:
    return cross_entropy(one_hot(targets), softmax(logits.reshape({B*T, V})))
return logits

GPT::Block<T>

Pre-norm residual block, the standard GPT-2 layout:

y = x + mha(ln1(x), apply_mask)
z = y + ffwd(ln2(y))
return z

Constructor validates input_dim % n_heads == 0 and throws otherwise (checked_head_size); head_size = input_dim / n_heads.

GPT::Head<T> — scaled dot-product attention

q, k, v = Q(x), K(x), V(x)                                 // each {B,T,head_size}
scores  = q.matmul(k.transpose({0,2,1})) / sqrt(head_size)
if apply_mask:
    scores += causal_mask                                   // -inf above the diagonal, tril-based
attn = softmax(scores)
return attn.matmul(v)

The causal mask is lazily rebuilt only when the sequence length changes (set_mask checks mask.shape[1] == seq before recomputing) — an important performance detail since tril/where are not free.

GPT::MultiHeadAttention<T>

Runs n_heads independent Heads, concatenates their outputs on the last axis ({B,T,head_size} × n_heads → {B,T,n_heads·head_size}), then projects back to input_dim through a final Linear (proJ).

GPT::FeedForward<T>

Two-layer MLP with a GeLU nonlinearity and a 4× hidden expansion (standard GPT-2 ratio): down(GeLU(up(x))) where up projects to 4 × input_dim.

GPT::generate(index, max_new_tokens=50, temperature=0.7, k=40)

Autoregressive sampling loop. Each step: crop context to max_sequence_length, run a forward pass, take the last timestep's logits, apply temperature scaling then top-k filtered softmax (topk_softmax: partial-sorts to the top k logits, zeroes the rest, softmaxes only the survivors), sample via Matrix::choice, append the token, repeat.

GPT::train(get_batch_fn, iters, eval_interval)

Owns its own Optimizer<T> (AdamW, lr=1e-4). Standard loop: fetch a batch, call train_step (zero_grad → forward → backward(1.0) → step), periodically evaluate on the "val" split, and call loss->reset_graph() every iteration.

Llama<T>

Llama(size_t vocab_size, size_t input_dim, size_t block_size, size_t n_heads, size_t n_layer, size_t ffn_hidden)

Same overall shape as GPT<T> with three architectural swaps: no separate positional-embedding table (RoPE is applied inside each attention head instead), RMSNorm instead of LayerNorm, and a SwiGLU feed-forward. An extra eos_token_id check (hardcoded to 2, i.e. <|im_end|>) lets generate() stop early for instruction-tuned checkpoints like SmolLM2-Instruct.

Llama::Head<T> — RoPE attention

Each head owns its own RotationalPositionalEncoding<T> instance (constructed with (head_size, sequence_length)). Q and K projections are rotated by RoPE before the scaled dot-product step; V is not.

Llama::FeedForward<T> — SwiGLU

gate   = SiLU(gate_proj(x))
up     = up_proj(x)
hidden = gate * up            // elementwise gating
return down_proj(hidden)

All three projections (gate_proj, up_proj, down_proj) are bias-free Linear layers — matching the Llama/SmolLM2 reference architecture, where SwiGLU replaces GPT-2's single-hidden-layer GeLU MLP.

GPTLoRA<T> — federated LoRA distillation student

Identical backbone to GPT<T> (position/token embedding, decoder blocks, final LayerNorm), but the LM head is a LoRALinear<T> instead of a plain Linear<T>. Full forward/generate logic is duplicated from GPT<T> rather than inherited, specifically so no plain-Linear head is ever allocated and wasted.

Why the LM head specifically

In a GPT-2-small-shaped model the LM head (vocab_size × d_model, e.g. 50257×768 ≈ 38.6M params) is the single largest weight matrix outside the token embedding, and the one tensor GPT.hpp already exposes cleanly enough to swap. The attention/MLP projections inside each Block are not currently LoRA-adapted — the pattern for extending that is noted directly in the source (templatize Block on its projection type).

Bridging from a pretrained GPT<T>

GPTGGUFLoader<T> only knows how to populate a GPT<T>, so weights are loaded into a normal GPT<T> first, then copied tensor-for-tensor:

GPTGGUFLoader<float> loader;
GPT<float> pretrained = loader.load_model(model_path, hp);

GPTLoRA<float> student(hp.vocab_size, hp.d_model, hp.block_size,
                       hp.n_head, hp.n_layer, /*rank=*/8, /*alpha=*/16.0f);
student.load_backbone_from(pretrained);   // position embed, token embed, ln_f, all blocks
student.load_head_from(pretrained);       // seeds lm_head.weight (frozen)
// `pretrained` can now be destroyed — weights were copied, not referenced.

lora_parameters() — the selective-training hook

GPTLoRA<T>::lora_parameters() returns only {A, B} from the LM head (the frozen weight was never registered as a parameter, by LoRALinear's own constructor). Trainer<Model,T> detects this method via SFINAE and builds its optimizer from it instead of the full parameters() list — so only the tiny adapter actually trains, while backward still walks the entire frozen backbone (this engine has no engine-level requires_grad cutoff, so backward cost is unchanged; what shrinks is optimizer state and, if you choose to send lora_parameters() over the wire instead of the full model, the federated payload).

backbone_parameters() returns everything except the adapter — for a split checkpoint pattern: quantize and save the (large, shared) backbone once, keep the (tiny, per-client) adapter in plain float.
