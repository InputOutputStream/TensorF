Operator overloads

Two files, two very different contracts. Overload.hpp operates on raw std::vector<T> with no broadcasting; tensor_overloads.hpp operates on Tensor_t<T> and builds autograd graph nodes. Read both before assuming += behaves the way you expect.

Overload.hpp — std::vector<T> arithmetic

The socket that Matrix<T>::operator+/-/*// sits on top of.

OperatorsBehavior
+ - * / (vector ⊕ vector) Iterates min(|a|,|b|) — no error and no broadcasting on mismatched sizes; truncates silently. See Known Issues #10.
+ - * / % (vector ⊕ scalar, both orders) Exception thrown on division by zero.
< > <= >= Return std::vector<T> (0/1 convention).
== != Return std::vector<uint8_t> — a different result type than the ordering comparisons above, despite being conceptually boolean too. See Known Issues #9.
+= -= *= /= Real in-place mutation here (contrast with Tensor_t below).

Math helpers

exponent(v)Elementwise exp
pow(v, T n)General power, with shortcuts for n=2,3,4
pow(v1, v2)Elementwise power of two vectors
check_nan(v)Detects NaN/Inf and calls std::abort() — a fundamentally different error strategy than Tensor::backward()'s recoverable exceptions. See Known Issues #8.

tensor_overloads.hpp — Tensor factory & graph operators

make_tensor<T>(...)

Overloads constructing a Tensor_t<T> from: nothing, a constant, a std::vector<T>, nested 1D/2D/3D initializer lists, a pointer/reference to Matrix<T>, or another Tensor_t<T> — each with a with/without Operation_t<T> variant.

Tensor_t<T> ⊕ Tensor_t<T>

+, -, *, /, pow(...) construct the corresponding Operation and return forward() — a fresh graph node every call. operator== compares values only, unrelated to the graph (non-differentiable).

Comparisons — outside the graph

==, !=, <, >, <=, >= (tensor/scalar) create a new Tensor_t with no Operation_t attached (backOp == nullptr) — explicitly commented "Non graph related ops" in the source.

API trap — compound assignment does not mutate +=, -=, *=, /= on Tensor_t<T> build a new Operation and return a new Tensor_t<T>. They do not mutate the left-hand tensor in place. Writing a += b; without reassigning (a = a += b;) changes nothing. This is a different contract than the same operators on std::vector<T> or Matrix<T>, which do mutate in place. See Known Issues #7.

Tensor_t<T> ⊕ scalar

+, -, *, /, pow, unary - (implemented as multiplication by the constant tensor −1) — each combination wraps the scalar via make_tensor<T>(a) and stays inside the graph (differentiable).
