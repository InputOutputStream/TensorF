Install & build

TensorF is header-only C++20 with three system dependencies. There is no package manager step — you compile the example or your own .cpp directly against include/.

Dependencies

LibraryWhyUbuntu/Debian package
g++ (C++20)Compiler. Needs <ranges> and structured bindings support.build-essential g++
OpenBLASMatrix::dot / matmul dispatch to cblas_sgemm / cblas_sdot for float/double. Optimizer uses cblas_saxpy/cblas_sscal.libopenblas-dev
nlohmann/jsonHeader-only JSON, used by the GPT-2 tokenizer's vocab.json loader and the Profiler's JSON payload.nlohmann-json3-dev
libxxhashOptional integrity hashing for the Profiler wire protocol (WAN-safe checksum, vs. CRC32 for LAN).libxxhash-dev
pthreadsThe federated Server's ThreadPool and socket handling.usually preinstalled
install everything on Ubuntu/Debian
make install-deps

This runs apt-get install build-essential g++ cmake pkg-config libopenblas-dev nlohmann-json3-dev libxxhash-dev wget curl.

verify what's actually detected on your machine
make check-deps

Prints the compiler version and whether OpenBLAS / nlohmann-json / pthreads were found via pkg-config or header presence, without installing anything.

git clone https://github.com/InputOutputStream/TensorF.git

Directory layout

The Makefile assumes this structure — it's already what the repo ships:

./                   ← Makefile, README
./examples/          ← entry points: GPT2.cpp, SmollLLM.cpp
./tests/             ← basic_tests.cpp, benchmark.cpp
./scripts/           ← download.sh
./docs/              ← this site
./gateway/           ← web management API (REST + WebSocket) for the dashboard
./include/
    core/             ← tensor engine
        DataStructures/  Matrix.hpp, Tensor.hpp
        Operations/      19 Operation<T> subclasses + base
        Overloads/       operator overloads (raw vector + Tensor_t)
        Types/           shape_t, Tensor_t, fp8/fp4 software float types
    nn/               ← models & layers
        Modules/         Linear, LayerNorm, RMSNorm, Embedding…
        Modules/Transformer/GPT, GPT-LORA, Llama
        ModelLoader/     GGUF → GPT<T> / Llama<T> weight loading
        Tokenizer/       byte-level BPE (GPT-2 + Llama family)
    data/             ← datasets
        DataLoader/      GGUF reader, image/tabular/text/NPY loaders, quantizer, serializer
    net/              ← federated learning networking
        Network/         Client, Server, Trainer, ThreadPool
        Protocol/        binary wire protocol for the Profiler
    tools/            ← profiling & benchmarking
        Profiler/        hardware fingerprint, benchmarks, hyperparameter advisor
./bin/              ← build output (created automatically)

Headers resolve via -Iinclude -Iinclude/core -Iinclude/nn -Iinclude/data -Iinclude/net -Iinclude/tools in the Makefile, so any header can be included by its bare subsystem name (e.g. #include "Types/types.hpp") regardless of which group folder it lives in.

Web management API

gateway/ is a standalone Boost.Beast HTTP + WebSocket server that manages the binaries above (server, client, benchmark, gpt2, smollm, tests) as jobs — launch, kill, and stream their logs live — without any changes to TensorF itself. It's the backend for the web dashboard.

make gateway              # builds bin/tensorf-gateway
make run-gateway          # build + run, defaults to PORT=8080, TENSORF_BIN_DIR=./bin

REST endpoints live under /api (job listing, launch, kill, health); a WebSocket at /ws streams job_started / log / job_exited events in real time. See Gateway API reference for the full route table.

Debug builds DEBUG=1 make tests compiles with -O0 -g3 -fsanitize=address,undefined instead of -O2. Use this when chasing the memory-safety issues noted on the Known Issues page — several are exactly the class of bug ASan/UBSan catch.

Downloading GGUF checkpoints

The GPT-2 and Llama example programs expect real GGUF files under SLM/. A helper script fetches them from Hugging Face:

chmod +x scripts/download.sh
mkdir -p SLM
./scripts/download.sh

By default this pulls GPT-2 small in three precisions (F32 full-precision, Q8_0, and Q4_K_S quantized) into SLM/gpt2-small-*.gguf. Larger GPT-2 variants (medium/large/XL) and SmolLM2 are commented out in the script — uncomment the lines you need, or point GPT2.cpp/SmollLLM.cpp at your own GGUF path.

Sanity check

make tests

Compiles and runs basic_tests.cpp, which cross-checks Matrix<T> arithmetic, matmul, transpose, and reductions against known NumPy outputs (each test prints [PASS]/[FAIL]). If this passes, OpenBLAS linking and the core tensor engine are working.
