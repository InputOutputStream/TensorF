Quickstart

Five short programs: raw tensor algebra, an autograd graph with a manual backward pass, a trainable Linear layer, a training loop with Optimizer, and loading a real GPT-2 checkpoint for text generation.

1. Matrix<T> — plain algebra, no gradients

Matrix<T> is the array type underneath everything. It supports NumPy-style construction, broadcasting, and BLAS-backed products but has no notion of a computation graph.

matrix_basics.cpp
#include "DataStructures/Matrix.hpp"
#include <iostream>

int main() {
    // 2D literal construction
    Matrix<float> a({{1,2},{3,4}});
    Matrix<float> b({{1,2},{3,4}});

    // matmul dispatches to cblas_sgemm for float/double
    Matrix<float> c = a.matmul(b);   // [[7,10],[15,22]]

    // broadcasting: {2,2} + {2} -> {2,2}, NumPy rules
    Matrix<float> row({10, 20});
    Matrix<float> d = c + row;

    std::cout << d.sum() << "\n";   // sum() with no axis -> scalar T
}

2. Tensor<T> — building and running an autograd graph

Every graph node is a Tensor_t<T> (std::shared_ptr<Tensor<T>>), created via make_tensor<T>. Arithmetic operators on Tensor_t build the graph implicitly; calling ->backward(...) walks it in reverse.

autograd_basics.cpp
#include "DataStructures/Tensor.hpp"
#include <iostream>

int main() {
    Tensor_t<float> x = make_tensor<float>(Matrix<float>({2.0f, 3.0f}));
    Tensor_t<float> w = make_tensor<float>(Matrix<float>({4.0f, 5.0f}));

    // y = sum(x * w)  — operator* on Tensor_t builds a MultiplyOperation node
    Tensor_t<float> y = (x * w)->sum();

    y->backward(make_tensor<float>((float)1.0));  // seed gradient = 1

    std::cout << "dy/dx = " << x->grad << "\n";  // == w's values, {4,5}
    std::cout << "dy/dw = " << w->grad << "\n";  // == x's values, {2,3}

    y->reset_graph();  // break the Tensor<->Operation shared_ptr cycle
}
Always call reset_graph() Tensor and Operation hold shared_ptrs to each other. Without calling reset_graph() after you're done with a graph (or its loss tensor), that memory leaks — the reference count never reaches zero. Training loops in this codebase call it every iteration; see Architecture → memory management.

3. A trainable layer with Module<T>

Layers subclass Module<T> and call register_parameter/register_module in their constructor. parameters() then recursively collects every learnable tensor for the optimizer.

linear_layer.cpp
#include "Modules/Linear.hpp"
#include "Modules/Optimizer.hpp"

int main() {
    Linear<float> layer(/*out_features=*/4, /*in_features=*/8);

    Tensor_t<float> x = make_tensor<float>(Matrix<float>::randn({1, 8}));
    Tensor_t<float> out = layer.forward(x);   // {1, 4} = x @ weight.T + bias

    Optimizer<float> opt(layer.parameters(), /*lr=*/1e-3f, ADAM);
    opt.zero_grad();
    out->sum()->backward(make_tensor<float>((float)1.0));
    opt.step();   // clips grad norm to 1.0, then applies Adam update
}

4. A minimal training loop

This is the shape every model's train() method in TensorF follows (see GPT::train, Llama::train, Trainer::finetune): zero grad → forward → backward → step → reset the graph.

training_loop.cpp
Optimizer<float> opt(model.parameters(), 1e-4f, ADAMw);

for (size_t iter = 0; iter < n_iters; iter++) {
    auto [inputs, targets] = get_batch("train");

    opt.zero_grad();
    Tensor_t<float> loss = model.forward(inputs, targets, /*apply_mask=*/true);
    loss->backward(make_tensor<float>((float)1.0));
    opt.step();

    if (iter % eval_interval == 0)
        std::cout << "iter " << iter << " loss " << loss->val << "\n";

    loss->reset_graph();   // critical — see the warning above
}

5. Loading a real GPT-2 checkpoint and generating text

This is the actual pattern from GPT2.cpp in the repo: load weights and tokenizer straight from a GGUF file, encode a prompt, and sample new tokens with top-k filtering.

GPT2.cpp (excerpt)
GPT2HyperParams hp {
    .vocab_size = 50257, .d_model = 768, .block_size = 1024,
    .n_layer = 12, .n_head = 12
};

GPTGGUFLoader<float> loader;
GPT<float> model = loader.load_model("SLM/gpt2-small-f32.gguf", hp);

GPT2Tokenizer tokenizer = loader.load_tokenizer();

std::vector<int> token_ids = tokenizer.encode("The data type is int");
std::vector<float> ctx_data(token_ids.begin(), token_ids.end());

Tensor_t<float> context = make_tensor<float>(
    Matrix<float>(ctx_data, {1, ctx_data.size()}));

// generate 30 new tokens, temperature 0.8, top-k = 30
auto out = model.generate(context, 30, 0.8f, 30);

std::cout << tokenizer.decode(/* tokens after the prompt */ ...);

Build and run this exact example with make gpt2 && ./bin/gpt2 (after downloading a GGUF checkpoint). See ModelLoader → GGUF weight-shape contract for how PyTorch's [out,in] layout maps onto GGUF's on-disk ordering.
