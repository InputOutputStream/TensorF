Tokenizer

Byte-level BPE tokenization, matching GPT-2's original algorithm and pre-tokenization regex. An abstract base handles everything shared; two subclasses differ only in encode()/decode() and how they're loaded.

Tokenizer — abstract base

class Tokenizer {
public:
    virtual ~Tokenizer() = default;
    virtual std::vector<int>  encode(const std::string& text) = 0;
    virtual std::string       decode(const std::vector<int>& ids) = 0;

protected:
    std::unordered_map<std::string, int> encoder;   // token_str -> id
    std::unordered_map<int, std::string> decoder;   // id -> token_str
    std::unordered_map<uint8_t, char32_t> byte_encoder;
    std::unordered_map<char32_t, uint8_t> byte_decoder;

    void build_byte_encoder();  // GPT-2's reversible byte<->unicode mapping
};

build_byte_encoder() implements GPT-2's specific byte-to-printable-unicode remapping: bytes that are already "nice" printable characters map to themselves, while the remaining 68 byte values (control characters, whitespace beyond space, etc.) map to unicode codepoints starting at U+0100 — this is what lets byte-level BPE merges operate on arbitrary binary input while every intermediate token remains representable as a normal string.

vocab_size()Returns encoder.size()
encode_special(tok)Looks up a special token (e.g. <|endoftext|>) directly by string, bypassing BPE merging

GPT2Tokenizer

void load_from_arrays(vector<string> vocab, vector<string> merges)

Populates encoder/decoder from the vocab list (index = token id) and builds the BPE merge-rank table from the merges list (earlier merges = higher priority, i.e. lower rank). This is the path used when loading a tokenizer straight out of a GGUF file's embedded metadata (see ModelLoader → GPTGGUFLoader::load_tokenizer).

void load_from_json(...)

Alternative loader that parses a standard Hugging Face vocab.json / merges.txt pair directly (via nlohmann/json), for when you have tokenizer files but not a GGUF checkpoint to pull metadata from.

vector<int> encode(string text) override
  1. Maps every raw byte of text through byte_encoder, re-encoding each mapped codepoint back to UTF-8.
  2. Runs the BPE merge algorithm (bpe(encoded)) on the resulting string to produce a list of subword pieces.
  3. Looks each piece up in encoder to get its final integer id.
string decode(vector<int> ids) override

Reverse of encode: looks up each id's token string, then maps every character back through byte_decoder to reconstruct the original bytes.

LlamaTokenizer

void load_from_gguf(vector<string> vocab, vector<pair<string,string>> merge_pairs)

Same vocab-loading logic as GPT2Tokenizer, but merges arrive already split into (left, right) pairs (GGUF's tokenizer.ggml.merges stores each rule as a single space-separated string; LlamaGGUFLoader::load_tokenizer splits it before calling this).

vector<int> encode(string text) override

Adds one behavior GPT2Tokenizer's encode doesn't need: scans for known special tokens (e.g. chat-template markers like <|im_start|>) embedded directly in the input string, encoding them via encode_special and falling back to normal byte-level BPE (encode_plain) for everything in between. This is what lets SmolLM2-Instruct chat-formatted prompts round-trip correctly.

Usage

GPT2Tokenizer tok = loader.load_tokenizer();

std::vector<int> ids = tok.encode("Hello, world!");
std::string   back = tok.decode(ids);   // == "Hello, world!"
