Matrix<T>

The N-dimensional array underneath everything in TensorF: flat std::vector<T> storage, row-major strides, NumPy-style broadcasting, and BLAS-backed products. No gradient tracking — that's Tensor<T>'s job.

Internal representation

Matrix.hpp — private members
std::vector<T> data;    // flat storage, row-major order
shape_t shape;           // e.g. {batch, seq_len, dim}
shape_t numElementsSeen; // precomputed strides (computeShapes)
mutable size_t size, ndims; // caches, resynced by get_size()/get_ndims()

shape_t is an alias for std::vector<size_t> (declared in Types/types.hpp). Strides are computed from the last dimension (stride = 1) working backward — standard row-major layout.

Constructors

About fifteen overloads cover: scalar (Matrix(const T&)), copy/pointer, flat std::vector<T> (with or without an explicit shape), std::vector<std::vector<T>> (2D), and nested initializer_lists up to 3 levels deep (1D/2D/3D literals like {{1,2},{3,4}}).

AVX2 padding Every constructor that takes an explicit shape calls verifyShape(), which accepts either a size exactly matching the product of dimensions, or one padded for AVX2 (avx2_pad(n) = ((n+7)/8)*8) — a hint that storage is meant to align on 8-element blocks for vectorized (SIMD) work. However, the actual padding-on-construction code is commented out, so this is currently inactive for general storage — only the output buffer of matmul/dot is really padded. See Known Issues #13.

Broadcasting — Broadcast<T>

A separate utility class, declared friend class Broadcast<T> of Matrix<T>, implementing NumPy-style broadcasting. Full description on the Architecture page. The operators +, -, *, / call it automatically whenever shapes differ.

Matrix products

dot(Matrix<T> rhs) BLAS-backed

Dispatches on dimensionality: 1D·1D → scalar product via a simple loop (dotProduct1D). 2D·2D → dotProduct2D, which calls cblas_sdot/cblas_ddot for float/double, else a naive loop (needed for fp8/fp4). Other shapes → checks dotShapesAssert then delegates to a generic path over matProduct2D.

matmul(Matrix<T> rhs) BLAS-backed

Rejects 1D·1D explicitly ("use dot() instead"). Computes the output shape (shape[:-1] + rhs.shape[-1]), allocates an AVX2-padded output buffer, then recurses over batch dimensions (indexStack) down to the last two, calling matProduct2D — backed by cblas_sgemm/cblas_dgemm for float/double. Natively supports a 2D weight matrix shared across a 3D batch (rhsStart stays 0 until batch dims of rhs are exhausted) — this is what lets a Linear layer's 2D weight multiply a {B,T,D} activation tensor.

Elementwise functions

exponent(), ln(), sqrt(), cbrt(), pow(T), pow(Matrix<T>) apply the scalar function elementwise and rebuild a same-shaped Matrix<T>.

ln() silently clamps ln() clamps input to a minimum of 1e-9f before taking the logarithm (protecting against log(0)/log(negative)) — but silently, with no warning or exception, and the clamp is not mirrored in LogOperation::backward, which divides by the raw t1. Near zero this makes the gradient potentially explosive. See Known Issues #4.

Critical — at(Matrix<bool>) missing return The branch that constructs res in the nominal case never returns a value — undefined behavior. This is called directly by IndexOperation::forward(), so Tensor::bool_index() is concretely affected. Fix this before relying on boolean indexing. See Known Issues #1.

OpenBLAS dependency

Matrix.hpp includes <cblas.h> directly and calls cblas_sdot/cblas_ddot/cblas_sgemm/cblas_dgemm for float/double. OpenBLAS must be linked at build time (see Install); custom types like fp8/fp4 always take the non-BLAS naive-loop fallback.
