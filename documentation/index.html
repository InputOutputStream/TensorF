A tensor & autograd engine built to train language models across a federation of ordinary machines.

TensorF is a from-scratch C++ deep learning framework: a NumPy-like Matrix<T>, a define-by-run autograd graph, GPT/Llama transformer implementations, GGUF model loading, and a federated learning stack (FedAvg + FedDistill) for training across clients that never share raw data.

What TensorF is

TensorF is a self-contained tensor library and neural network toolkit written in modern C++ (C++20), designed around the same mental model as PyTorch's autograd — a dynamic, define-by-run computation graph — but implemented from first principles on top of std::vector storage and OpenBLAS for the heavy linear algebra. On top of that engine sits a full GPT-2 and Llama/SmolLM2-compatible transformer stack that can load real GGUF checkpoints, run inference, fine-tune, and participate in a federated training round with other machines over a plain TCP socket.

Tensor engine

Row-major Matrix<T> with NumPy-style broadcasting, batched matmul via OpenBLAS, and a Tensor<T> graph node wired through 19 Operation<T> subclasses.

Transformers

GPT-2-style and Llama/SmolLM2-style decoder stacks, plus a LoRA-adapted GPT variant built for federated distillation with a frozen backbone.

Federated learning

A TCP client/server pair implementing FedAvg (weight averaging) and FedDistill (soft-logit consensus) with chunked, low-RAM-friendly wire protocols.

GGUF model loading

Reads real GGUF checkpoints (GPT-2, SmolLM2/Llama) including quantized tensor formats, with a byte-level BPE tokenizer compatible with the Hugging Face vocab/merges format.

Hardware-aware training

A Profiler subsystem fingerprints CPU/ISA/RAM/cache/storage and derives batch size, block size, and quantization policy per client — so federated rounds adapt to weak devices.

Quantization

Custom software FP8 / FP4 types with block-wise absmax scaling for ~4×–8× smaller checkpoints on disk and over the wire.

Three layers do the heavy lifting: Matrix<T> is pure algebra with no notion of gradients; Operation<T> subclasses know how to run forward and backpropagate through themselves; Tensor<T> is the graph node the user actually touches, always via a Tensor_t<T> = std::shared_ptr<Tensor<T>>.
